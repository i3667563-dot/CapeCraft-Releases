# CapeCraft Fire

Условие `when` по горению игрока. Отдельный аддон: состояний сущности в Minecraft
столько же, сколько их там будет завтра, и перечислять их в моде — значит
обновлять мод под каждое новое.

## Что появляется в конфиге

```kn
capeCraft {
    providers [
        { name = "fireman", type = "url", url = "https://скеп/cape.png",
          when = { fire.burning: "true" }, priority = 2 }
    ]
}
```

Корень `fire`:

| Поле | Тип | Что значит |
|---|---|---|
| `fire.burning` | `true` / `false` | Горит ли игрок. Поле по умолчанию, поэтому `when = { fire: "true" }` — то же самое |
| `fire.ticks` | число | Сколько тиков осталось гореть. `0` — не горит. Понимает `>`, `>=`, `<`, `<=` |

## Кто это видит

Только владелец плаща. Состояние сущности соседа наблюдателю неизвестно, поэтому
условие помечено локальным и по сети не объявляется: я поджёг свой плащ, у соседа
он не появился.

## Установка

1. Мод CapeCraft 1.3.0 или новее.
2. Этот jar в ту же папку `mods`.

Редактор подхватывает описание сам: jar лежит в `mods`, сервер LSP читает
`capecraft-addon.kn` из него, и `fire` появляется в подсказках и автодополнении.
Подробности — в [API.md](../../API.md), раздел «Условия `when`».

## Сборка

```bash
# мод должен быть собран: аддон компилируется ровно против того jar'а, что и
# положит игрок, и версию берёт из gradle.properties мода
cd ../.. && ./gradlew jar -Pmc=26.2

cd addons/capecraft-fire && ./gradlew build
# jar: build/libs/capecraft-fire-1.0.0.jar
```

Путь к jar'у мода можно задать явно:

```bash
./gradlew build -Pcapecraft_jar=/путь/к/capecraft-1.3.0-26.2.jar
```

## Тесты

```bash
./gradlew test
```

- `FireCapeAddonTest` сверяет дескриптор из jar'а с тем, что аддон регистрирует в
  рантайме. Формы независимы, и без сверки расхождение выглядит исправно с обеих
  сторон: в редакторе поле есть, в игре конфиг падает.
- `PackagedJarTest` смотрит в собранный jar: точка входа в `fabric.mod.json`
  существует, класс на месте, дескриптор упакован.
