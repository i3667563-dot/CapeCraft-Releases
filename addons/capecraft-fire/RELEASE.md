# capecraft-fire 1.0.0

Первый аддон с условием `when` по состоянию сущности.

Мод больше не перечисляет такие состояния у себя: их столько же, сколько их
будет в следующей версии Minecraft, и список успевал устареть раньше, чем им
начинали пользоваться. Корни `when` объявляет аддон.

## Установка

1. [CapeCraft 1.3.0](https://github.com/i3667563-dot/CapeCraft-Releases/releases/tag/v1.3.0)
   или новее — в нём `API version 2` и реестр `api.whenConditions`.
2. Этот jar в ту же папку `mods`.

Ядро аддону не нужно: условие читает состояние сущности, а не картинку.

## Что появляется в конфиге

Корень `fire` с полями:

| Поле | Тип | Что значит |
|---|---|---|
| `fire.burning` | `true` / `false` | Горит ли игрок. Поле по умолчанию: `fire: "true"` — то же самое |
| `fire.ticks` | число | Сколько тиков осталось гореть, `0` — не горит |

```kn
capeCraft {
    providers [
        { name = "fireman", type = "url", url = "https://скеп/cape.png",
          when = { fire.burning: "true" }, priority = 2 }
    ]
}
```

Числа понимают `>`, `>=`, `<`, `<=` и диапазон `63..80` — как `location.y`.

## Кто это видит

Только владелец плаща. Состояние сущности соседа наблюдателю неизвестно,
поэтому условие помечено локальным и по сети не объявляется: подожёшь своего
плаща — он не появится у соседа, и это не ошибка.

## Редактор

Описание лежит в jar'е (`capecraft-addon.kn`), LSP читает его из папки `mods`
рядом с конфигом: `fire` появляется в автодополнении, `fire.burning` и
`fire.ticks` — среди полей, значения — в подсказке. Переустановил аддон —
переоткрывать файл не нужно, сервер сам перечитает папку.

Если подсказки не появились, сначала проверь, что мод 1.3.0 или новее: на 1.2.x
корня `fire` не существует, и конфиг с ним падает при загрузке.

## Требования

Minecraft 26.2, Fabric Loader 0.19.5+, Fabric Language Kotlin, CapeCraft 1.3.0+.
Java 21 и новее — байт-код аддона собран под 21.

## Сборка из исходников

```bash
# мод должен быть собран: аддон компилируется ровно против того jar'а, что и
# положит игрок
cd ../.. && ./gradlew jar -Pmc=26.2

cd addons/capecraft-fire && ./gradlew build
```

Путь к jar'у мода можно задать явно:
`./gradlew build -Pcapecraft_jar=/путь/к/capecraft-1.3.0-26.2.jar`

Тесты (`./gradlew test`) сверяют описание из jar'а с тем, что аддон регистрирует
в рантайме, и проверяют байт-код: игра на Java 25 не прочитает класс, собранный
под 26, и падение выглядело бы как «мод сломался».
