# Changelog

## 1.2 — 2026-09-30

### Добавлено: условия брони, здоровья и состояния

- **У `when` появились три новых корня.** `armor` (`head`, `chest`, `legs`,
  `feet`) отдаёт тир надетой брони — `none`, `leather`, `chainmail`, `iron`,
  `gold`, `diamond`, `netherite`, `turtle`; короткая запись `armor: "diamond"`
  означает `armor.chest`. `health` (`current`, `max`) — числа, поэтому
  работают `">10"`, `"10..20"`. `state` (`inWater`, `sneaking`, `sprinting`,
  `onGround`, `pose`) — логические значения и поза игрока.
- **У `health` и `state` нет короткой записи.** `health: 20` — ошибка при
  загрузке с перечнем полей: «какое здоровье» без уточнения не имеет смысла.
  Редактор ловит это до запуска игры, с готовыми правками.
- **Публичные `armor` и `health` едут в синхронизацию** (Sync v4, теги 5 и 6):
  получатель считает их по наблюдаемому игроку, как и остальные условия `when`.
- **`state` — self-only и не уезжает по сети.** Провайдер с любым `state`
  становится локальным целиком, даже если остальные его условия публичные:
  смешивать в одном провайдере бессмысленно, половина всё равно не уедет.
- **Ключ провайдера `self = true`** скрывает провайдера от других игроков
  вручную. Работает и без `when`: провайдер считается условным (побеждает
  «просто на всякий случай»), но в сети не объявляется.
- **Протокол синхронизации поднят до v4.** Старый клиент и мод 1.2 не поймут
  друг друга — версия проверяется первым байтом пакета.

### Исправлено

- KDoc схемы `when` больше не обещает вложенный словарь (`biome { id = ... }`),
  который мод отвергает: условие пишется плоским ключом с точкой.
- `API.md` указывал на несуществующий путь к примеру аддона; реальный пример
  версионный (`versions/<mc>/src/test/.../examples/ExampleCapeAddon.kt`),
  потому что модификаторы рендера работают с классами клиента.
- README получил раздел «Аддоны» со ссылкой на `API.md` и описанием новых
  условий `when`.

### Добавлено: условие `if`

- **У провайдера появился ключ `if`.** В отличие от `when` (мир того, кто
  смотрит), `if` проверяет переменные: `username`, `uuid`, `name`, `root`,
  `$ИМЯ` и аддонные плейсхолдеры. Операторы те же: `"prod"`, `"!dev"`,
  `">8000"`, `"63..80"`.
- **`$` включает провайдера ровно тогда, когда переменная есть.** Пока
  `$TIER` не определена, условие не выполнено и провайдер не участвует;
  появилась со значением — участвует с того же момента. Число из окружения
  понимается как число: `if = { $PORT: ">8000" }` сработает на `PORT=9000`.
  Читается сырое имя переменной, без префикса `CAPECRAFT_`.
- **`when` и `if` соединяются по И.** Нужны оба.
- **Корень мира в `if` — ошибка при загрузке**, а не молчаливый «не подошло»:
  перенесённый `when` ловится сразу. Неизвестное имя (аддон ещё не
  установлен) — наоборот, обычное «не подошло».
- **Условие `if` едет в синхронизацию** (Sync v4): получатель считает его сам
  по своим переменным; совместимость со старыми клиентами разрывается
  бампом версии каналов и внятным отказом.

### Изменено: `priority` работает на всех провайдеров

- Раньше `priority` упорядочивал только провайдеров с условиями, а
  безусловные шли в порядке списка — цифра у них была ключом, который
  редактор подсвечивал, а мод не читал. Теперь внутри каждой группы
  (условные и безусловные отдельно) — по убыванию `priority`, при равном —
  порядок в списке. Безусловный провайдер не перебивает подошедшее условие
  никаким приоритетом.

## 1.1.2

### Исправлено: `CAPECRAFT_CONFIG` больше не выключает мод целиком

- **Недоступный файл из окружения больше не оставляет мод без плащей.** Переменная
  `CAPECRAFT_CONFIG` (или `-Dcapecraft.config`) задана, а файла по ней нет —
  опечатка в пути, ещё не смонтированный том, конфиг переехал на другую машину.
  Раньше `CapeConfig.reload()` писал одну строку в лог и выходил, оставляя **ноль
  провайдеров** и дефолтные лимиты: плащей не видно, в чате ничего не сказано, а
  разгадать можно было только по логу. Теперь такой файл не заменяет конфиг, а
  только сообщает о себе — читается обычный `config/capecraft.kn` (или legacy
  `.crn`), а причина уходит в лог **и** в `/cp status`. Мод с плащами лучше мода
  без плащей, даже если плащи не те.
- **`/cp reload` больше не врёт о том, какой конфиг прочитан.** Команда печатала
  `cfg.path`, а это всегда `config/capecraft.kn`: при внешнем файле человек видел
  путь, который мод не открывал, и отличить свой конфиг от чужого было нечем. Теперь
  печатается `activeSource` — реально прочитанный файл.
- **Причина отката видна в чате.** `/cp reload` дописывает строкой
  `ВНИМАНИЕ: <причина>`, а `/cp status` показывает `Конфиг: <путь>` и эту же
  причину (и ошибку конфига, если она есть) отдельными строками. Раньше откат был
  виден только в логе.

Решение о выборе файла вынесено в `CapeConfigFiles.resolve()` вместе с признаками
`createDefault`/`warning`/`fromEnv` — там же тесты, потому что `CapeConfig` при
создании тянет `FabricLoader` и юнит-тестом не поднимается.

## 1.1.1

### Изменено: набор для объекта без синхронизации

- **Объект без объявления больше не остаётся без плаща.** Раньше игрок, который
  не участвует в цепочке синхронизации (нет мода, `serverSync.enabled = false`,
  сервер не CapeCraft), получал на экране ровно ничего: мод видел его, но
  показывать ему было нечего. Провайдеры-то адресуются по `{username}` и
  `{uuid}` — плащ зарегистрированного у твоего провайдера человека находится
  тем же запросом, что и любой другой. Теперь такому объекту мод даёт
  [ObjectCapePolicy.ANNOUNCE_GRACE_MS] (5 секунд) на объявление, а по
  истечении срока навязывает свой локальный набор. Правило: объявился — его
  набор со его `when` и приоритетами; не объявился — мой; пришедшее позже
  объявление перебивает навязанный набор.
- **Пустое объявление больше не значит «показать нечего».** Клиент без
  провайдеров объявляет пустой список — `announce` шлётся всегда, даже когда
  набор пуст, — и правило трактовало это как объявление. Итог: игрок без
  конфига навсегда оставался без плаща, хотя его плащ находится тем же
  запросом по `{username}`, а пятисекундный срок ожидания не срабатывал
  вовсе, потому что «молчания» не было. Теперь пустое объявление означает
  «набора нет» и даёт мой локальный набор — сразу, без ожидания: объявление
  уже пришло, ждать тут нечего. Найдено живым прогоном на двух клиентах
  (GGSHNIKK с web-провайдером, Eonixx без провайдеров, оба аккаунта на одном
  провайдере): плащ Eonixx не показывался вообще, хотя его у провайдера был.
  Непустое объявление по-прежнему главнее моего набора, а свой набор — раньше
  всего.
- **Свой `file`-плащ не терялся на входе на сервер.** Сервер рассылает снимок
  роустера всем, включая объявившего, а локальный файл по умолчанию наружу не
  уезжает (`shareLocalProviders = false`) — в своём же снимке его нет. Раньше
  «свой» брался из роустера, и локальный плащ исчезал ровно в момент входа.
  Теперь свой набор берётся из локального конфига всегда.
- **`/cp reload` пересчитывает и навязанные наборы.** Раньше он перезагружал
  только мой собственный плащ, потому что чужие объекты «живут по объявленным
  ими наборам». Для навязанных это неверно: они держатся на моём конфиге, и его
  смена обязана их обновлять. Объявленные наборы по-прежнему не трогаются.
- **Плащи и GPU-текстуры молчащих игроков не переживают выход с сервера.** На
  `DISCONNECT` чистился цикл по `knownObjectIds`, а он перечисляет только
  объявившихся. Плащи остальных оставались в кэше и показывались на следующем
  сервере вместе с чужим набором провайдеров. Заодно сбрасывался свой id:
  при выключенной синхронизации он в `knownObjectIds` не попадал вовсе и уезжал
  на следующий сервер. Теперь это `forgetSession()`.

### Исправлено

- **Планировалась загрузка без провайдеров.** `ensureLoading` ставил фоновую
  задачу даже при пустом наборе — то есть на каждом кадре рендера, все пять
  секунд ожидания объявления, с ошибкой «нет провайдеров» в `/cp list` и
  событием `ProviderNotFound` на каждый кадр. Теперь пустой набор выходит
  сразу.

## 1.1.0

Мод переехал из файлов конфигурации в окружение лаунчера, а синхронизация
плащей переписана в объектную модель, где у каждого игрока своя функция,
свой приоритет и свои условия.

### Исправлено в 1.1.0 по ходу живых прогонов

  Оба бага найдены не тестами, а на двух настоящих клиентах: тесты покрывали
  состояние, а не то, кто его двигает и как сервер раздаёт чанки.

  - **Докачка картинки больше одного чанка не начиналась.** Клиент звал
    `onTick()` раз в 20 тиков, а внутри состояния был свой счётчик игровых
    тиков, который никто не двигал. Первый `fetch` уходил, а условие «не
    раньше следующей попытки» уже никогда не проходило: за сессию ровно один
    запрос. Счётчик двигается в том же `onTick()`, а сам `onTick()` зовётся
    каждый игровой тик — иначе внутренняя шкала отставала от игрового времени
    в 20 раз. Троттлинг аплоада (раз в 20 тиков) вынесен из
    `publishOwnedImages`, который раньше дёргался на каждом вызове.
  - **Сервер объявлял размером картинки размер первого куска.** `totalSize`
    считался как `chunk.size + offset`, то есть для первого запроса это всегда
    64 КиБ. Клиент собирал из пяти кусков буфер в 64 КиБ, хэш не сходился, и
    все куски отбрасывались: `чанк отброшен: хеш не совпал`. Размер теперь
    берётся у хранилища через `ImageStore.sizeOf(hash)`.
  - **Дефолтный `config/capecraft.kn` врал.** В шаблоне остались ключи v1
    (`intervalTicks`, `timeoutTicks`, `requireServer`, `allowFileProviders`),
    которые `ServerSyncSettings` не читает, и два активных провайдера-заглушки,
    из-за чего чистая установка считала своими `example.com` и несуществующий
    локальный файл. Все примеры закомментированы, ключи — v2.

### Переделано: синхронизация

- **Синхронизация стала объектной.** Раньше сервер держал «каталог плащей» и
  отдавал его целиком всем, а приоритет был один на весь список. Теперь каждый
  игрок — отдельный объект со своим набором функций: свой `priority`, свои
  `when`-условия, своя картинка. Условия считаются против мира **наблюдаемого**
  игрока, а не моего: джунглевый плащ показывается только тому, кто смотрит
  действительно из джунглей.
- Клиент больше не присылает свой id и имя — сервер берёт их от отправителя,
  подделать чужой набор нельзя в принципе.
- Снимок роустера приходит целиком, а не дельтой: пропущенный join или leave
  (краш, рестарт, лаг) самолечится, а не оставляет чужой набор навсегда.
- Локальный `file` по умолчанию не раздаётся (`shareLocalProviders=false`), и путь
  на провод не уходит никогда — вместо него передаётся SHA-256, а байты клиент
  забирает у владельца через сервер кусками по 64 КиБ.
- Аддон-провайдеры не синхронизируются: выполнять чужой аддонный код с
  параметрами, придуманными на стороне объявившего, нельзя.

### Исправлено: синхронизация

- **Смена картинки при том же имени больше не игнорируется.** Отпечаток набора
  считался по одному только имени провайдера, поэтому игрок, поменявший плащ и
  оставивший подпись прежней, оставался со старой текстурой до перезахода.
  Теперь в отпечатке источник, приоритет, условие и наличие аддона.
- **Файлы больше чанка досылаются.** Свои картинки отдавались по одному куску и
  только по событиям (вход, смена набора, реконнект), но не по тику: плащ тяжелее
  64 КиБ намертво залипал на первом куске. Теперь отправка продолжается каждый тик.
- **Уходя с сервера, клиент освобождает чужие плащи.** На выходе сбрасывалось
  только состояние синхронизации, а байты и GPU-текстуры чужих игроков жили до
  конца сессии и накапливались на каждом заходе.
- **Обрезанный снимок больше не выкидывает живые наборы.** Сервер отбрасывает
  самые давно не переобъявлявшиеся объявления, когда снимок не влезает в лимит.
  Клиент при этом считал отсутствие игрока его уходом и сносил его набор, так
  что на переполненном сервере плащи у длинного хвоста онлайна мигали. Теперь
  в обрезанном снимке отсутствие ничего не значит.
- **`allowForeignUrls` начал действовать.** Настройка была объявлена и
  разбиралась из конфига, но не применялась: чужие ссылки подхватывались всегда.
  Теперь при `false` чужие `url`/`json` игнорируются, а `file` по хэшу — нет,
  он приходит через сервер, а не по чужому адресу.
- **Потолок по числу игроков стал настоящим.** `RosterStore` принимал
  `maxPlayers`, но нигде его не использовал, так что лимита не существовало.
  Теперь при превышении вытесняется самый давно не переобъявлявший.
- **Картинка больше одного чанка не собиралась никогда.** Докачка зависала на
  первом куске: планировщик пропускал картинку, у которой сборка уже начата,
  считая это «идёт, не трогай», поэтому запрос на второй кусок не
  формировался ни разу. Владелец при этом честно отдавал все куски, а
  получатель их не запрашивал.
- **Владелец не отдавал собственный файл.** Публиковались «свои объявления
  плюс то, на что ссылаются чужие», а собственный файл не ссылался никто — он и
  не уходил. Теперь свои файлы публикуются, когда в лобби есть кто-то ещё.
- **Докачка спрашивала кусок с нуля каждый раз.** Вместо места обрыва
  отправлялось смещение 0, поэтому уже принятые байты запрашивались заново и
  картинка не доходила до конца никогда.
- **Медленная передача выглядела зависшей.** Таймаут ожидания был жёстко зашит
  на 200 тиков, а интервал между попытками при неудачах доходит до 1200.
  Нормальный перенос с паузами всегда попадал под таймаут: начатое отбрасывалось,
  запрос уходил с нуля, и передача начиналась по кругу. Теперь таймаут
  считается от интервала ожидания, и разброс упирается в потолок вместе с ним.
- **Успешная передача копила интервал.** Backoff рос на каждой попытке и не
  сбрасывался, когда куски приходили: после первых неудач картинка в 8 МиБ шла
  по чанку в минуту. Теперь реальный прогресс возвращает интервал к базовому,
  но не раньше него — иначе куски шли бы вплотную и заваливали сервер.
- **Частое объявление больше не теряется.** Троттлинг ограничивает частоту
  объявлений, а не их приём: два `/cp reload` подряд оставляли игрока со старым
  плащем, потому что второе объявление молча отбрасывалось. Теперь отброшенное
  объявление ждёт очереди и уходит на ближайшем тике сервера, как только
  прошло две секунды.
- Зависшая докачка больше не живёт вечно: без прогресса дольше двух интервалов
  ожидания частичная картинка отбрасывается, и запрос повторяется с нуля.
- Путь локального файла и количество условий больше не уезжают на провод при
  ошибке конфигурации: путь стирается на кодировании, лимит предикатов
  проверяется тоже на кодировании, а не только на разборе.


Конфигурация мода переехала из файла в окружение: теперь мод настраивается
прямо из настроек лаунчера или из аргументов запуска, без доступа к папке
игры. Заодно закрыт баг, из-за которого анимированный плащ растягивался на всю
текстуру, и починены `/cp reload` с `/cp clear`.

### Добавлено

- **Переопределение настроек через переменные окружения и `-D`.** Не отдельная
  функция, а способ переопределить ключи поверх файла `config/capecraft.kn`.
  `CAPECRAFT_CONFIG=/path.kn`
  читает конфиг из произвольного файла вместо `config/capecraft.kn` — единственный
  способ задать провайдеры из окружения. Точечные переопределения лимитов и
  синхронизации задаются именем, которое строится механически:
  `capeCraft.limits.maxFrames` → `CAPECRAFT_LIMITS_MAXFRAMES` или
  `-DcapeCraft.limits.maxFrames=20`. Приоритет: переменная → `-D` → файл → дефолт.
- `/cp status` показывает активные переопределения из окружения. Без этого
  нельзя было понять, откуда взялось неожиданное значение: переменная
  перебивает `.kn` молча.
- Переопределение с нечитаемым значением не ломает мод: берётся значение из
  файла, в лог уходит предупреждение с именем переменной.
- Задача `publishArtifact`: сборка сама копирует jar в
  `artifacts/capecraft-<версия>-<mc>.jar`.
- **Поддержка Stacked PNG** — анимация в одном PNG. Размер кадра берётся из
