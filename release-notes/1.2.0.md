## CapeCraft 1.2.0

Кастомные анимированные плащи для Minecraft 1.21.1 / 1.21.4 / 1.21.8 / 1.21.10 / 1.21.11 / 26.2

### ⚠️ Обновляться всем сразу

Синхронизация поднята до протокола **v4**, и это несовместимое изменение. Мод
1.2 и мод 1.1.2 не поймут друг друга: версия проверяется первым байтом пакета,
и несовпавший пакет отбрасывается на разборе — намеренно, потому что читать
чужой формат посимвольно значит сдвинуть весь поток и получить тихую порчу
вместо внятного отказа.

Будь готов: отбрасывание выглядит как «плащи просто перестали приходить».
Понятной ошибки в чате не будет, в обычном логе тоже ничего (на сервере запись
есть, но уровнем `debug`, её не видно). Так что если после частичного
обновления плащи пропали — сначала проверь версии на сервере и клиентах, и
доведи до одной.

### ⚠️ Если в конфиге есть `${NAME-дефолт}`

Одиночный дефис больше не отделяет дефолт. Он стал частью имени, чтобы
переменные можно было называть `BASE-URL`, а `${A-B}` — это переменная `A-B`.
Дефолт пишется только как `${NAME:-дефолт}`.

Конфиг при этом не сломается, но дефолт перестанет подставляться: адрес станет
пустым, и в лог уйдёт предупреждение с именем переменной. Если у тебя есть
такая запись — перепиши её на `${NAME:-дефолт}` перед обновлением. Найти
помогает то самое предупреждение в логе.

### Установка

1. Установи [Fabric Loader](https://fabricmc.net/) для своей версии Minecraft
2. Скопируй нужный `capecraft-1.2-<версия>.jar` в папку `mods`
3. Запусти игру

### Поддерживаемые форматы

PNG • Stacked PNG • APNG • GIF • WebP (lossless)

### Конфигурация

`config/capecraft.kn` — создаётся автоматически при первом запуске.
Полный список ключей и разбор настроек — в
[README](https://github.com/i3667563-dot/CapeCraft-Releases/blob/main/README.md).

Существующий конфиг не перезаписывается: 1.2 читает твой файл как есть, новые
ключи в него не дописываются.

### Что нового

**У провайдера появился ключ `if`.** Раньше условие (`when`) могло смотреть
только на мир: погода, время, биом, координаты. Теперь появился блок, который
смотрит на сам набор данных — кто смотрит, что запущено, что лежит в
окружении. Там, где `when` отвечает на «какая сейчас погода», `if` отвечает на
«этот ли это игрок и этот ли это запуск».

```
capeCraft {
    providers [
        { name = "trusted", type = "url", url = "https://example.com/trusted.png",
          if = { username: "Eonixx" } },

        { name = "prod", type = "url", url = "https://example.com/prod.png",
          if = { $DEPLOY_ENV: "prod" } },

        { name = "high-port", type = "url", url = "https://example.com/p.png",
          if = { $PORT: ">8000" } },

        { name = "default", type = "url", url = "https://example.com/{username}.png" }
    ]
}
```

Читаются: `username`, `uuid`, `name`, `root`, переменные окружения `$ИМЯ` и
плейсхолдеры, которые отдают аддоны. Операторы те же, что и в `when`:
`"prod"`, `"!dev"`, `">8000"`, `"63..80"`. Число из окружения понимается как
число, а не как строка, поэтому `$PORT: ">8000"` работает на `PORT=9000`.

**`$` включает провайдера ровно тогда, когда переменная есть.** Пока `$TIER` не
задана, условие просто не выполнено, и провайдер не участвует — без ошибки и
без «случайно сработало на пустом значении». Переменная появилась с нужным
значением — провайдер включился; убрали или поменяли — выключился. Читается
сырое имя, без префикса `CAPECRAFT_`: `$CAPE_HOST` в `if` — это `CAPE_HOST` из
окружения, тогда как в `url` подстановка `$CAPE_HOST` читает
`CAPECRAFT_CAPE_HOST`. Всё как в самом формате `.kn`, ничего нового
придумывать не надо.

**`when` и `if` соединяются по И.** Нужны оба, чтобы провайдер был выбран.

**Корень мира в `if` — ошибка при загрузке.** Если скопировать рабочий `when` в
`if` и забыть переписать, ловишь ошибку сразу, а не вечное «не подошло» без
причины. Неизвестное имя (аддон ещё не установлен) — наоборот, обычное «не
подошло»: подсветка не ругается на чужие имена.

**`priority` теперь работает и на провайдеров без условий.** Раньше цифра у
безусловного провайдера была ключом, который редактор подсвечивал, а мод не
читал. Теперь внутри каждой группы — по убыванию `priority`, при равном
порядок в списке. При этом условие по-прежнему важнее приоритета: безусловный
провайдер с `priority = 100` не перебьёт подошедшее условие с `priority = 1`.
Число задаёт порядок внутри группы, а не право перебить осознанный выбор.

**Условие едет в синхронизацию.** Получатель считает `if` сам, по своим
переменным: плащ, объявленный сервером для «своего» игрока, не показывается
чужим. Отсюда и бамп протокола до v4 — см. предупреждение выше.

**У `when` появились броня, здоровье и своё состояние.** Раньше условие могло
спросить только про мир вокруг: погода, время, биом, координаты. Теперь можно
спросить про самого игрока:

```
capeCraft {
    providers [
        { name = "hurt", type = "url", url = "https://example.com/hurt.png",
          when = { health.current: "<10" } },

        { name = "diamond", type = "url", url = "https://example.com/diamond.png",
          when = { armor.chest: "diamond" } },

        { name = "water", type = "url", url = "https://example.com/water.png",
          when = { state.inWater: true } },

        { name = "default", type = "url", url = "https://example.com/{username}.png" }
    ]
}
```

- **Броня** — `armor.head`, `armor.chest`, `armor.legs`, `armor.feet`. Тир один
  на слот: `none`, `leather`, `chainmail`, `iron`, `gold`, `diamond`,
  `netherite`, `turtle`. Короткая запись `armor: "diamond"` — это `armor.chest`.
- **Здоровье** — `health.current` и `health.max`, оба числа, поэтому работают
  `">10"`, `"<5"`, `"10..20"`. Короткой записи нет: `health` без поля — ошибка,
  потому что «какое здоровье» без уточнения не имеет смысла.
- **Состояние** — `state.inWater`, `state.sneaking`, `state.sprinting`,
  `state.onGround` (значения `true`/`false`) и `state.pose` (`standing`,
  `crouching`, `swimming`, `fall_flying`, `sleeping`, `spin_attack`,
  `long_jumping`, `dying`).

**Броня и здоровье видны другим, состояние — нет.** Условие `state` описывает
того, кто *надел* плащ, а не того, кто на него смотрит, поэтому считается оно
только у владельца и **не уезжает по сети**. Провайдер с любым `state`
автоматически становится локальным целиком: смешивать в одном провайдере
публичные и self-only условия бессмысленно, половина всё равно не уедет.

Тот же флаг можно поставить руками — `self = true`, — если публичные условия
писать не хочется, а плащ нужно оставить себе. Он работает и совсем без `when`:
такой провайдер считается условным (побеждает «просто на всякий случай»), но в
сети не объявляется.

**Редактор знает про новые условия.** Подсказки предлагают новые корни, поля и
значения, а `health: 20` без поля теперь подсвечивается сразу, с перечнем того,
что можно написать, — раньше такая ошибка всплывала только при запуске игры.

**Имена переменных окружения стали строже, а пропажа переменной — не ошибка.**

Имя теперь буквы, цифры, `_` и `-`, и начинаться оно должно с буквы или `_`.
Дефис разрешён ради имён вида `BASE-URL` — в лаунчере и в systemd-юните такое
имя обычное дело. Всё остальное имя обрывает, так что при `BASE=localhost:8080`
запись `url = "$BASE/api/cape.png"` даст `localhost:8080/api/cape.png`: на слэше
имя кончилось, хвост дописался как есть. Так же ведут себя точка, запятая,
двоеточие и пробел.

**Незаданная переменная больше не роняет конфиг.** Раньше `$CAPE_HOST` без
самой `CAPE_HOST` в окружении был ошибкой разбора, и из-за одного адреса не
работали все плащи разом — а это самое обычное дело, когда конфиг перенесли с
другого сервера. Теперь на место подставляется пустая строка, конфиг грузится
целиком, а в лог уходит одно предупреждение с именем переменной: молча пустой
`url` в логе выглядел бы так же, как заданный адрес, и плащ просто перестал бы
грузиться. Незакрытая `${` и неверное имя вроде `${1BAD}` по-прежнему ошибки.

### Исправлено

- Ошибка о повторяющемся имени больше не говорит «встречается 2 раз» и не
  молчит о том, где искать. Теперь она называет позиции всех дубликатов,
  готовые варианты с номером и считает по-русски:
  `неоднозначная ссылка: «capeCraft» встречается 2 раза (строки 12 и 34).
  Укажите номер: «capeCraft1» или «capeCraft2». Либо переименуйте один из них.`
  Раньше оставалось только догадаться, что «2» — это про два блока
  `capeCraft`, и искать их глазами по всему конфигу. Редактор и игра говорят
  одно и то же.
- `if { username: ... }` теперь считается и для собственного плаща: раньше
  ник локального игрока не доезжал до проверки, и условие по нему не
  срабатывало никогда.
- Уход игрока больше не оставляет его плащ в видеопамяти. GPU-текстура и её
  `NativeImage` жили до конца процесса: `forget(uuid)` был написан, но **не
  вызывался из одного места** — нигде. На длинной сессии с большим онлайном
  это копится до нехватки видеопамяти, и страдает уже игра, а не мод.
  Теперь `ensureLoading` отмечает, что объект только что был в кадре, а раз в
  секунду реестр освобождает всё, чего не было в кадре дольше 10 секунд.
  Порог не «нет в кадре», а «нет давно»: игрок за стеной рисуется не каждый
  кадр, и мгновенная проверка выбрасывала бы текстуры у живых. Локального
  игрока подчистка не трогает — его плащ нужен в каждом кадре.
- Записи о провайдерах больше не переживают выход с сервера: `usernames` и
  порядок применения удаляются вместе с игроком, а не копятся до конца
  процесса по одной строке на каждого, кого мод хоть раз видел.
- Плащ не грузился: `TextureManager.getTexture()` — не «спросить, есть ли
  текстура», а мутация. На отсутствующем id он создавал `SimpleTexture`,
  **регистрировал** его и пытался загрузить ресурс, поэтому проверка «есть ли
  у нас плащ» сама порождала `Missing resource capecraft:cape/... referenced
  from itself`, а следующий `release` закрывал уже не нашу сломанную текстуру —
  `Failed to close texture`. Теперь у мода свой реестр текстур: чужое под его
  id не трогается, а своё известно наверняка. Заодно освобождение уходит на
  рендер-поток: `close()` освобождает GL-ресурсы, а звали его и с сетевого
  (сброс сессии при переподключении), и с воркерского потока.
- Документация аддонов больше не обещает форму `when`, которую мод отвергает:
  условие пишется плоским ключом с точкой (`biome.precipitation = "snow"`),
  вложенный словарь в `when` не разбирается. Путь к примеру аддона в API.md
  исправлен на реальный — он версионный, потому что модификаторы рендера
  работают с классами клиента.

### Проверено

- Шесть версий: BUILD SUCCESSFUL, полный набор тестов на каждой, 0 failures
  (1041 тестов).

- `/cp list` перестал быть списком байтов в памяти и стал ответом на вопрос
  «почему показался не тот плащ». Он считает отбор тем же
  `ProviderSelector`, что и рендер, и печатает: цепочку загрузки, кто первый
  на экране, а по каждому провайдеру — все проверки с фактическим значением,
  ожиданием и галочкой. Например, почему не подошёл полный незерит с
  элитрами:

  ```
  → netherite приоритет 14 — не подходит
        ✗ armor.chest: unknown = netherite
        ✗ armor.head: none = netherite
        ✓ armor.legs: netherite = netherite
        ✓ armor.feet: netherite = netherite
  + fallback — без условий, всегда в цепочке
  ```

  Видно и полезное: если между последним пересчётом и командой сменилось
  состояние мира, выводится и тот порядок, который реально применён к
  текстуре, — иначе картинка на экране старая, и это легко принять за ошибку
  отбора.

  Важно: проверки внутри `when` соединяются через AND, и `when` с `if` — тоже.
  OR между условиями не выражается; чтобы «либо элитры, либо незерит», нужно
  разнести варианты по провайдерам и задать приоритет.
- Подстановка окружения жадная и случается на разборе, поэтому `$` в ключе
  условия — отдельный случай: имя должно дойти до модели как `$ИМЯ`, а не
  превратиться в значение. Это покрыто тестами на обоих парсерах (игра и
  редактор) и проверено мутациями в обе стороны: откат «`$` всегда значение»
  роняет 12 тестов, «`$` всегда ключ» роняет 10.
- Редактор и игра обязаны решать одно и то же — это проверяется отдельным
  тестом согласия на кусочках конфига, включая `$` в ключе.
