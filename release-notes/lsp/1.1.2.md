# capecraft-lsp 1.1.2

Убранный аддон теперь виден на файле, а не только в значке.

## Что исправлено

**Сервер отдал диагностику мгновенно, а на файле ничего не изменилось.** Живой
прогон в редакторе: аддон вынесли из `mods`, значок в статусной строке показал
«2 бага», а подсветки на конфиге не было и подсказки не появились. Причина в
серьёзности, а не в доставке.

`providers.type` — открытое поле: его словарь дополняют аддоны. Значение не из
словаря уходило в `HINT` (severity 3) с оговоркой «если это не тип от аддона».
Оговорка верная только тогда, когда сервер ничего не видел. Теперь сервер
различает два случая:

- **папка `mods` найдена** — перечень исчерпывающий: `url`, `json`, `file` плюс
  всё, что принесли аддоны. Значение не из этого списка — **ошибка**: мод не
  соберёт такого провайдера, и конфиг не загрузится;
- **папки `mods` нет** (LSP запущен вне экземпляра игры, файлы приходят по
  сети, дескриптора нет у части аддонов) — поведение прежнее, `HINT` с
  оговоркой.

Проверять это в редакторе вручную не нужно: значение не из словаря помечается
ошибкой, а на месте остаётся быстрое исправление — заменить на `url`, `json`
или `file`.

## Что это не меняет

Наблюдение за `mods`, подпись кэша и всё остальное из 1.1.1 — как было. На игру
не влияет: мод файл не читает.

## Проверено

- 1109 тестов сервера и мода, падений нет;
- тест на анализаторе: при найденной папке `mods` неизвестный тип — `ERROR`,
  при ненайденной — `HINT`; на прежнем коде первый падает с `expected
  <ERROR> but was: <HINT>`;
- тест на живом сервере: после удаления аддона приходит `severity 1` с
  сообщением про `«seed»`, и тип больше не предлагается в подсказках. Без
  наблюдателя падает по таймауту, с прежней серьёзностью — по `severity`;
- сквозной прогон настоящего `capecraft-lsp.jar` как отдельного процесса: папка
  `mods` меняется на лету, приходит ошибка с severity 1 без единого запроса от
  клиента.
