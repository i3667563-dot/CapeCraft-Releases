# capecraft-lsp 1.1.4

Аддонские корни `when` в редакторе.

Мод обновлён до 1.3.0: аддон может объявлять свои корни `when`, и они приходят
в редактор из того же jar'а, что и типы провайдеров.

## Что появилось

Секция `conditions` в `capecraft-addon.kn`:

```kn
addon {
    id = "capecraft-fire"
    version = "1.0.0"
    apiVersion = 2

    conditions = [
        {
            id = "fire",
            doc = "Горение игрока.",
            defaultField = "burning",
            fields = [
                { name = "burning", doc = "Горит ли игрок.", values = ["true", "false"] },
                { name = "ticks", doc = "Сколько тиков горит.", numeric = true }
            ]
        }
    ]
}
```

С ним `fire` ведёт себя как встроенный корень: предлагается в автодополнении,
`fire.burning` и `fire.ticks` — среди полей, значения — в подсказке, числа
понимают `>`, `>=`, `<`, `<=` как `location.y`.

## Три отличия, которые видно в редакторе

- **Условие всегда местное.** Состояние сущности известно только владельцу
  плаща, поэтому провайдер с таким корнем не объявляется по сети. Подсказка
  говорит об этом прямо — иначе человек решил бы, что условие не сработало
  из-за бага.
- **Встроенное имя не перекрывается.** Аддон с корнем `weather` не подменяет
  встроенный, а получает строку в stderr сервера.
- **Из двух аддонов с одинаковым корнем побеждает первый.** Порядок jar'ов в
  папке `mods` меняется при переустановке, поэтому на такое имя полагаться
  нельзя — сервер скажет об этом в stderr.

## Проверено на живом конфиге

Сервер поднят как отдельный процесс над настоящей папкой `BedWarsV11`, в ней
стояли `capecraft-fire` и `capecraft-seed`. На рабочем конфиге с провайдером
`fireman` и `when = { fire.burning: "true" }` — ноль диагностик, а в
автодополнении `fire`, `fire.burning` и `fire.ticks`.

Сам дескриптор из jar'а аддона в редакторе не исполняется: читается zip-архив,
никакого чужого кода в classpath сервера. Поэтому опечатка в дескрипторе
выглядит как «подсказок нет», и аддон обязан сверять описание со своим
значением — тестом, а не человеком.

## Формат

Те же правила, что у обычного конфига: записи блока `addon { }` — переводом
строки, пары внутри `{ }` — запятой. Запятая после `id = "..."` в блоке
`addon` не разбирается, и это самая частая причина «дескриптор не прочитан».
