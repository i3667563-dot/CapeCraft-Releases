# capecraft-lsp 1.0.0

Первый стабильный релиз.

Language Server для конфигов CapeCraft — `.kn`/`.crn` (язык
[KoreN](https://github.com/i3667563-dot/koren), Kotlin-порт формата Cren
[Kjen](https://github.com/i3667563-dot/kjen)). Один `java -jar`, без Minecraft
внутри: серверу не нужна игра, ему достаточно разобрать конфиг.

Репозиторий — общий с модом, но это отдельный артефакт **со своей версией**:
релизы мода и сервера не зависят друг от друга.

## Почему 1.0.0

Бета была не «работает наполовину», а «не проверено на живых конфигах».
Проверено: сервер поднят как настоящий процесс, над ним прогнан JSON-RPC
(`initialize` → `didOpen` → `diagnostic` → `shutdown`), и на реальном рабочем
конфиге из девяти провайдеров он даёт **ноль ошибок** — девять подсказок
severity 3 по значениям полей (`armor.chest`, `location.y`, `state.inWater`).

Отдельно проверено, что сервер не мешает самому конфигу: подсказки берутся из
того же словаря ключей, на котором игра проверяет `when`, поэтому ключ,
принятый редактором, не может оказаться незнакомым игре.

## Что умеет

- подсказки ключей / значений / типов, у корня `when` и блоков — сниппеты;
- hover: документация ключа и его дефолт;
- диагностика: опечатки в ключах, неверные типы, неизвестные провайдеры,
  незакрытые строки и скобки; `codeAction` превращает исправления из
  диагностики в готовые `TextEdit`;
- семантическая подсветка (комментарии, строки, числа, ключи, типы,
  подстановки `${...}`), свёртывание блоков, дерево символов документа;
- поддержка кодировок позиций `utf-16`/`utf-8`/`utf-32` — эмодзи в конфиге не
  сдвигают курсор и подсветку.

Словарь ключей живёт в сервере, а не в настройках редактора, поэтому второго
списка ключей, который разошёлся бы с игрой, просто не существует.

## Подключение

**Zed** — расширение `tools/zed-koren`:
`CAPECRAFT_LSP_JAR` указывает на этот jar, дальше `./tools/zed-koren/install.sh`.

**Neovim** — `vim.lsp.config("capecraft", { cmd = { "java", "-jar", "<сюда>" } })`.

Любой другой LSP-клиент: `languageId` любой (сервер его не читает), файл
отдаётся как обычно.

## Чего пока нет

- go-to-definition, references, rename, formatting;
- delta-семантические токены (есть только `full`);
- запуск прямо из выпадающего списка LSP: jar нужно скачать и указать путь
  (или `CAPECRAFT_LSP_JAR` для расширения Zed).

Это не блокеры: то, что сервер уже умеет, работает целиком, а остальное —
недостающие отдельные возможности, а не недоделанные существующие.

Сборка сервера и документация: `docs/lsp/README.md` в
[i3667563-dot/CapeCraft](https://github.com/i3667563-dot/CapeCraft).
