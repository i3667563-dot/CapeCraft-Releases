## CapeCraft 1.1.0

Кастомные анимированные плащи для Minecraft 1.21.1 / 1.21.4 / 1.21.8 / 1.21.10 / 1.21.11 / 26.2

### Установка

1. Установи [Fabric Loader](https://fabricmc.net/) для своей версии Minecraft
2. Скопируй нужный `capecraft-1.1.0-<версия>.jar` в папку `mods`
3. Запусти игру

### Поддерживаемые форматы

PNG • Stacked PNG • APNG • GIF • WebP (lossless)

### Конфигурация

`config/capecraft.kn` — создаётся автоматически при первом запуске.
Полный список ключей и разбор настроек — в
[README](https://github.com/i3667563-dot/CapeCraft-Releases/blob/main/README.md).

### Что нового

**Синхронизация плащей.** В 1.0.0 её не было вообще: каждый показывал свой
плащ, и на сервере это ничем не управлялось. Теперь плащи можно раздавать
другим игрокам, и сервер решает, кто кому что показывает.

- Клиент объявляет *функции*: конкретные наборы плащей, которые он готов
  показывать. Имя сервера, приоритет и условия не участвуют в выборе набора.
- Сервер сам берёт идентификатор отправителя, хранит объявления и рассылает
  снимки. Кому какой плащ показывать, он не решает.
- Условия и приоритет считаются **против контекста того, на кого смотрит
  игрок**. Два игрока, смотрящие друг на друга, видят разные вещи — это
  задумано, а не баг.
- `source` и `extract` не уезжают по сети: получателю не нужен путь к файлу
  отправителя, картинка приходит через сервер.
- Локальные `file`-плащи раздаются нарезкой по 64 КиБ и докачиваются с места
  обрыва. По сети уходит только SHA-256.
- Обрезанный снимок роустера не читается как «игрок ушёл»: отсутствие в
  обрезанном снимке ничего не значит.

**Условия `when`.** Приоритет и условия считаются против мира наблюдаемого
игрока, а не против мира отправителя. Условие проверяет, что цель существует,
находится в прицеле, на близком расстоянии и так далее; игрок, на которого
смотрят, не видит собственный плащ, пока не смотрит на другого.

**Поддержка Stacked PNG.** Формат, где кадры анимации лежат в одном PNG, раньше
не распознавался и растягивался на весь плащ. Теперь размер берётся из того, что
объявляет сам файл, — анимация занимает ровно свою область.

### Исправлено

- **`/cp reload` больше не пустой.** Локальный конфиг не применялся, кэш и
  GPU-текстуры оставались прежними. Теперь это полная перезагрузка — конфиг,
  набор провайдеров, кэш, текстуры.
- `/cp clear` починен по назначению: раньше сбрасывал в том числе авторитетность
  сервера, из-за чего мод мог остаться без локального набора. Теперь трогает
  только кэш.
- **Условия `when` перестали быть наполовину мёртвыми.** `biome` без поля и его
  синонимы (`when { biome: "snowy" }`) опирались на поля, которых живой мир не
  отдавал ни в клиенте, ни на сервере: значение всегда было `"unknown"`, и условие
  молча не совпадало никогда. Теперь мир отдаёт `biome.id` и
  `biome.precipitation` (`snow` / `rain` / `none`) — во всех шести версиях. Заодно
  `time: "dawn"` и `time: "dusk"` переводились в несуществующие периоды вместо
  `sunrise` и `sunset`, а ошибка для `location` без поля советовала
  несуществующее `location.id`.
- **Подстановка окружения без кавычек перестала ломать конфиг.** Конструкции
  `${NAME}`, `${NAME:-дефолт}` и `${NAME-дефолт}` без кавычек падали с ошибкой
  парсинга, хотя в кавычках работали. Теперь работают в обоих виде, включая
  составные значения вида `${HOST}/capes/${PORT}/плащ.png`.
- **Неверный тип больше не проходит молча.** Подстановка окружения всегда даёт
  строку, поэтому `maxBytesTotal = "${CAPE_CACHE_BYTES}"` не мог стать числом, и
  мод тихо подставлял свой дефолт, не написав ни строки в лог. Теперь такое
  место пишет в лог, что ожидалось, что оказалось строкой, и каким
  переопределением это правится.
- **В README добавлены `when` и `$`-переменные** — обе фичи были не описаны
  вообще. Заодно исправлен пример провайдеров: между элементами массива нужны
  запятые, и без них конфиг не грузился.

### Проверено

- Шесть версий: 623 теста на версию, 3738 суммарно, 0 failures.
- Все примеры конфигов из README компилируются тестом: приём в сплошных
  блоках не пропускает опечатку, и документация не может разъехаться с кодом.
- Три новых теста на подстановку проверены откатом фикса: на старой версии
  токенизатора падают все три.
- Живой прогон на двух настоящих клиентах против тестового сервера: http-плащ
  256x128 и файловый плащ 294681 байт, который сервер нарезал на 5 кусков по
  64 КиБ. Сервер принял `картинка ea98e41084ac загружена (294681 байт)`, оба
  клиента получили `картинка ea98e41084ac докачана (294681 байт)`, ноль
  отбракованных кусков и ноль исключений. Владелец видит свой плащ, второй игрок
  — чужой.
- Набор синхронизации проверен мутацией: девять намеренных пороков, каждый
  роняет от двух до пяти тестов.
