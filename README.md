# CapeCraft

Кастомные анимированные плащи для Minecraft **1.21.1 / 1.21.4 / 1.21.8 / 1.21.10 / 1.21.11 / 26.2** (Fabric). Поддержка PNG, Stacked PNG, APNG, GIF и WebP — включая полную анимацию с прозрачностью и бесконечным циклом. Все версии собираются из одного репозитория.

Полный список изменений — в [CHANGELOG.md](CHANGELOG.md).

## Перед обновлением

**Обновляй всех сразу.** Мод 1.2 и мод 1.1.x не поймут друг друга: протокол
синхронизации поднят до v4, версия проверяется первым байтом пакета, и
несовпавший пакет отбрасывается на разборе. Отбрасывание выглядит как «плащи
просто перестали приходить» — внятной ошибки в чате нет, в обычном логе тоже
ничего (на сервере запись есть, но уровнем `debug`).

**Версия Minecraft не связана с версией мода.** Один и тот же `1.2.0` ставится
на все шесть версий, jar отличается только суффиксом. Мод 1.2.0 требует Java 21
(для 26.2 при сборке из исходников нужен JDK 26) и Fabric Loader 0.19.3+.

**Путь на диске не менялся:** `config/capecraft.kn` и `capecraft` в корне игры
переезжают как есть, старый конфиг читается новым модом. Ключи, которые в
протоколе 1.x были рабочими, а в v2+ стали пустыми (`intervalTicks`,
`timeoutTicks`, `requireServer`, `allowFileProviders`), мод игнорирует — их
можно удалить, а можно оставить.

## Установка

1. Установи [Fabric Loader](https://fabricmc.net/) для своей версии Minecraft
2. Скопируй `capecraft-1.2.0-<версия>.jar` из [Releases](https://github.com/i3667563-dot/CapeCraft-Releases/releases) в папку `mods/`, где `<версия>` — твоя версия Minecraft из списка выше
3. Запусти игру — мод загрузится автоматически

**Требования:** Fabric API, Fabric Language Kotlin (оба входят в стандартные сборки Fabric).

## Сборка из исходников

Версия выбирается флагом `-Pmc` (дефолт — 26.2):

```bash
./gradlew build -Pmc=1.21.1      # и 1.21.4, 1.21.8, 1.21.10, 1.21.11 (yarn, JDK 21)
./gradlew build -Pmc=26.2        # сборка под Minecraft 26.2 (необфусц., JDK 26)
```

Собираются они независимо, каждая под своим маппингом: 1.21.x берут yarn,
26.2 — необфусцированные имена Mojang. Проверить все шесть разом:

```bash
for v in 1.21.1 1.21.4 1.21.8 1.21.10 1.21.11 26.2; do
  ./gradlew test build -Pmc=$v --console=plain || break
done
```

Тесты — обязательная часть: `build` без `test` прогоняет только компиляцию, а
именно тесты ловят расхождение между версионными исходниками (например, что
`26.2` и `1.21.8` читают поле мира по-разному). Код, общий для всех версий,
лежит в `src/main/kotlin`; расходящийся — в `versions/<mc>/`.

Сборка сама копирует готовый jar в `artifacts/capecraft-<версия>-<mc>.jar`.
Ставь мод **только из `artifacts/`**: файлы там всегда от текущей сборки, а
`build/<mc>/libs/` и тем более старый jar из `mods/` могут оказаться
не той версии — мод запустится, но поведёт себя не так, как собран (см.
`AGENTS.md`, раздел «artifacts/ — ставить ТОЛЬКО отсюда»).

В `artifacts/` копится история прошлых сборок — файлы старых версий там не
перезаписываются. Перед релизом лишнее стоит снести, иначе легко взять не тот
jar: правильный — самый свежий по дате, с текущим `mod_version`.

## Редактор: LSP для `.kn`

Для конфигов есть Language Server: подсказки ключей и значений, проверка
ошибок, документация по наведению и быстрые правки опечаток.

Имена ключей и корни `when` берутся из тех же констант, что читает мод
(`ProviderNames.Keys`, `WorldRoot`, `Condition.LIVE_FIELDS`, `Limits`), поэтому
подсказка не может предложить ключ, которого в моде нет. При этом LSP
строже мода: неизвестный ключ он подчёркивает, а мод такой ключ молча
игнорирует.

```bash
./gradlew lspJar        # -> artifacts/capecraft-lsp.jar
```

Нужен только JRE (Java 21+), Minecraft и Fabric не требуются: в jar нет ни
одного класса от них. Подключение к Neovim:

```lua
vim.filetype.add({ extension = { kn = "kn", crn = "kn" } })

vim.lsp.config("capecraft", {
  cmd = { "java", "-jar", "/путь/к/CapeCraft/artifacts/capecraft-lsp.jar" },
  filetypes = { "kn" },
  root_dir = function(bufnr, on_dir)
    -- Именно on_dir: в vim.lsp.config результат return игнорируется.
    on_dir(vim.fs.dirname(vim.api.nvim_buf_get_name(bufnr)))
  end,
})
vim.lsp.enable("capecraft")
```

Умеет: `initialize`, синхронизация документа (`didOpen`/`didChange`/`didSave`/
`didClose`), `completion` (в том числе сниппеты, достраивающие блоки),
`hover`, `codeAction` с готовой правкой, `documentSymbol` (дерево
`capeCraft → блоки → ключи`, для старых клиентов — плоский список),
`foldingRange`, `semanticTokens/full` (цвет ключей, строк, чисел, комментариев
и подстановок `${...}`), диагностика (пушится сама и по запросу
`textDocument/diagnostic`), `shutdown`/`exit`.

Позиции считаются в той кодировке, которую выбрал клиент в
`general.positionEncodings` (`utf-16`, `utf-8`, `utf-32`; по умолчанию —
`utf-16`), поэтому эмодзи и другие символы вне BMP не сдвигают ни курсор, ни
подчёркивание диагностики, ни длину цветного токена.

Словарь ключей для подсветки берётся из того же места, что и подсказки, —
второго списка в редакторе нет и появиться не может. В Neovim сама подсветка
включается автоматически (начиная с 0.12), но группы `@lsp.type.*` нужно
назвать: имя у них с хвостом filetype, а темы заводят без него.

### Zed

В Zed настройками settings.json не обойтись: там можно переопределить
свойства уже известного языка, но не завести новый. Нужно расширение на
WASI-компонент, которое и регистрирует язык KoreN для `.kn`/`.crn`, и
поднимает сервер:

```bash
./tools/zed-koren/install.sh
```

Скрипт собирает `wasm32-wasip2`, кладёт расширение в
`~/.local/share/zed/extensions/installed/koren/` и добавляет запись в
`index.json`. После перезапуска Zed в `settings.json` нужно оставить:

```json
"languages": {
  "KoreN": {
    "semantic_tokens": "full",
    "language_servers": ["capecraft"]
  }
}
```

`full`, а не `combined`: tree-sitter-грамматики у KoreN нет, и всё
цветовое оформление приходит из semantic tokens сервера.

Подробное описание сервера — `docs/lsp/README.md`.

## Конфигурация

При первом запуске создаётся `config/capecraft.kn`. Формат — [KoreN](https://github.com/i3667563-dot/koren) (Minecraft-aware `.kn`), поверх [Kjen](https://github.com/i3667563-dot/kjen) — Kotlin-порта формата Cren. Минималистично и читаемо: вложенность обозначается отступами, списки — квадратными скобками.

### Провайдеры

Провайдеры — источники плащей. Проверяются по порядку: первый успешный отдаёт плащ.

```
capeCraft {
    providers [
        # Прямая ссылка на картинку
        { name = "example", type = "url", url = "https://example.com/capes/{username}.png" },

        # JSON-API: извлекаем URL из ответа по пути
        { name = "api", type = "json", url = "https://api.example.com/cape?u={username}", extract = "$.data.cape_url" },

        # Локальный файл
        { name = "local", type = "file", path = "{root}/capes/{uuid}.png" }
    ]
}
```

### Условия `when`

Плащ не обязательно один. У провайдера может быть блок `when` — тогда он
работает только в подходящих обстоятельствах, а в остальное время мод берёт
следующий по списку.

```
capeCraft {
    providers [
        { name = "rain",  type = "url", url = "https://example.com/rain.png",
          when = { weather: "rain" } },

        { name = "night", type = "url", url = "https://example.com/night.png",
          when = { time.period: "night", dimension: "overworld" } },

        { name = "deep",  type = "url", url = "https://example.com/deep.png",
          when = { location.y: ">-20" }, priority = 10 },

        { name = "default", type = "url", url = "https://example.com/{username}.png" }
    ]
}
```

**Что доступно.** Ключ условия — `корень.поле`, значение — что ждём увидеть:

| Корень | Поле | Что отдаёт | Поле по умолчанию |
|---|---|---|---|
| `biome` | `id` | id биома, например `minecraft:snowy_plains` | `id` |
| `biome` | `temperature` | базовая температура, число | — |
| `biome` | `precipitation` | `snow` / `rain` / `none` | — |
| `weather` | `condition` | `clear` / `rain` / `thunder` | `condition` |
| `time` | `period` | `day` / `sunset` / `night` / `sunrise` | `period` |
| `time` | `tick` | время суток в тиках, число | — |
| `dimension` | `type` | `overworld` / `nether` / `end` | `type` |
| `dimension` | `id` | полный id, например `minecraft:the_nether` | — |
| `location` | `x`, `y`, `z` | координаты, число | нет, писать обязательно |
| `armor` | `head`, `chest`, `legs`, `feet` | тир надетой брони: `none` / `leather` / `chainmail` / `iron` / `gold` / `diamond` / `netherite` / `turtle` | `chest` |
| `health` | `current`, `max` | здоровье, число | нет, писать обязательно |
| `state` | `inWater`, `sneaking`, `sprinting`, `onGround` | `true` / `false` | нет, писать обязательно |
| `state` | `pose` | `standing` / `crouching` / `swimming` / `fall_flying` / `sleeping` / `spin_attack` / `long_jumping` / `dying` | нет, писать обязательно |

**Операторы** живут в значении:

| Значение | Смысл |
|---|---|
| `"snowy_plains"` | равно |
| `"!rain"` | не равно |
| `">63"`, `">=63"`, `"<100"`, `"<=100"` | числовое сравнение |
| `"63..80"` | диапазон включительно |

**Короткая запись.** Если поле опустить, работают синонимы:
`when = { weather: "rain" }` — то же, что `weather.condition: "rain"`.

| Коротко | Разворачивается в |
|---|---|
| `biome: "snowy"`, `"snow"`, `"frozen"` | `biome.precipitation: "snow"` |
| `biome: "rain"`, `"rainy"` | `biome.precipitation: "rain"` |
| `weather: "clear"`, `"fair"` | `weather.condition: "clear"` |
| `weather: "rain"`, `"rainy"` | `weather.condition: "rain"` |
| `weather: "thunder"`, `"storm"` | `weather.condition: "thunder"` |
| `time: "day"` | `time.period: "day"` |
| `time: "dawn"`, `"sunrise"` | `time.period: "sunrise"` |
| `time: "dusk"`, `"sunset"` | `time.period: "sunset"` |
| `time: "night"`, `"midnight"` | `time.period: "night"` |
| `dimension: "overworld"` | `dimension.type: "overworld"` |
| `dimension: "nether"`, `"the_nether"` | `dimension.type: "nether"` |
| `dimension: "end"`, `"the_end"` | `dimension.type: "end"` |

**Все условия внутри блока соединяются по И.** Пустой `when = { }` — «всегда».

Знак перед `{` обязателен: внутри словаря (`when = { ... }`) блок без `=` или `:`
мод не прочитает — в отличие от верхнего `capeCraft { ... }`, где знака не надо.

**Чьи условия считаются.** Для своего плаща — по твоему миру. Для чужого — по
миру того, кого ты видишь: объявленный набор функций принадлежит ему. Стоит
владелец в джунглях, а ты смотришь на него из пустыни — ты всё равно увидишь его
«джунглевый» плащ. Вышел он из джунглей — плащ перестанет показываться, даже
если ты сам остался в джунглях. Погода, время и измерение тут общие: чужого
игрока видно только в твоём измерении.

**Недоступное поле — это «не подошло», а не ошибка.** Если сущности нет (плащ
ещё не загружен) или поле временно недоступно, условие просто не выполняется.
Опечатки, наоборот, ловятся сразу при загрузке конфига: неизвестный корень,
слишком глубокий путь вроде `time.period.extra` или `location` без поля — понятное
сообщение с перечнем доступного.

**Только свои условия: `state` и `self`.** Условие `state` (поза, вода, красться,
бег, стоять на земле) описывает того, кто *надел* плащ, а не того, кто на него
смотрит, поэтому оно считается только у владельца и **не уезжает по сети**: чужой
клиент такого провайдера просто не увидит. Провайдер с любым `state`
автоматически становится локальным целиком — смешивать в одном провайдере
публичные и self-only условия бессмысленно, половина всё равно не уедет.

Тот же флаг можно поставить руками, если публичные условия писать не хочется, а
провайдер нужно оставить себе:

```
capeCraft {
    providers [
        { name = "armored", type = "url", url = "https://example.com/armor.png",
          when = { armor.chest: "diamond" }, self = true },

        { name = "swimming", type = "url", url = "https://example.com/water.png",
          when = { state.inWater: true } },

        { name = "default", type = "url", url = "https://example.com/{username}.png" }
    ]
}
```

Здесь `swimming` локален сам собой, из-за `state.inWater`, а `armored` —
публичное условие, но `self = true` всё равно оставляет плащ себе. Флаг работает
и совсем без `when`: такой провайдер считается условным (то есть побеждает
провайдеров «просто на всякий случай»), но в сети не объявляется.

**Кто выигрывает.** Сначала провайдеры, чьи условия выполнились. Потом
провайдеры вовсе без `when`. Поэтому дефолтный провайдер с `when` не нужен:
достаточно последнего в списке.

Внутри каждой группы — сначала те, у кого больше `priority` (по умолчанию `0`,
при равном — порядок в списке). `priority` работает и на провайдеров с условием,
и на тех, у кого его нет: два «просто на всякий случай» без условия
перебираются в порядке, который задаёт именно `priority`.

Условие важнее приоритета: безусловный провайдер с `priority = 100` не
перебьёт подошедшее условие с `priority = 1`. Число задаёт порядок внутри
группы, а не право перебить осознанный выбор.

### Условия `if`

Блок `when` смотрит на мир, а `if` — на **сам набор данных**: кто смотрит, что
запущено, что лежит в окружении. Там, где `when` отвечает на «какая сейчас
погода», `if` отвечает на «этот ли это игрок и этот ли это запуск».

```
capeCraft {
    providers [
        { name = "trusted", type = "url", url = "https://example.com/{username}.png",
          if = { username: "Eonixx" } },

        { name = "prod", type = "url", url = "https://example.com/prod.png",
          if = { $DEPLOY_ENV: "prod" } },

        { name = "dev", type = "url", url = "https://example.com/dev.png",
          if = { $DEPLOY_ENV: "dev" }, priority = 10 },

        { name = "default", type = "url", url = "https://example.com/{username}.png" }
    ]
}
```

**Что доступно.** Ключ условия — имя переменной целиком, значение — что ждём
увидеть:

| Имя | Что это |
|---|---|
| `username` | Имя профиля игрока, как в `{username}` |
| `uuid` | UUID без дефисов, как в `{uuid}` |
| `name` | Имя провайдера |
| `root` | Папка игры, как в `{root}` |
| `$ИМЯ` | Переменная окружения **с этим именем как есть** |
| плейсхолдер аддона | всё, что аддон отдаёт в `{...}` |

**Про окружение.** Здесь `$` — это сырое имя переменной, без префиксов: в
`if` ключ `$CAPE_HOST` читает `CAPE_HOST` из окружения, тогда как в `url`
подстановка `$CAPE_HOST` читает `CAPECRAFT_CAPE_HOST`. Ключ условия
разбирается позже, когда переменная уже может появиться, поэтому и не
подставляется на старте.

Ключ пишется как есть, без кавычек: `if = { $TIER: "gold" }`. Имя после `$` —
это имя переменной окружения, поэтому буквы, цифры, `_` и `-`, как в подстановке
(`${TIER}` тоже можно). Точка в имени — уже аддонный плейсхолдер
(`if = { myAddon.level: ">=10" }`), а не переменная окружения. Имя с
пробелом, точкой или `=` в `$` не записать — будет ошибка загрузки.

Пока переменной нет, условие просто не выполнено, и провайдер не
используется — ровно тогда, когда её нет. Ни ошибки, ни «случайно сработало на
пустом значении»: провайдер включается в момент, когда переменная появилась с
нужным значением, и выключается, когда её убрали или поменяли.

**Операторы те же,** что в `when`: `"prod"`, `"!dev"`, `">8000"`, `"63..80"`.
Переменная окружения всегда строка, но мод понимает, что она числовая, если
так вышло: `if = { $PORT: ">8000" }` сработает на `PORT=9000`.

**Все условия внутри блока соединяются по И,** и вместе с `when` тоже: нужны
оба. `when = { weather: "rain" }, if = { username: "Eonixx" }` — «дождь **и**
этот игрок».

**Ключ — это имя целиком, а не путь.** Точка в нём значащая: `{ $TIER: ... }`
и `{ myAddon.level: ... }` ищут переменные с такими именами. Короткой записи
в `if` нет намеренно: без неё `{ time: "night" }` выглядело бы как «переменная
времени», а на деле это корень мира.

**Корень мира в `if` — ошибка при загрузке.** Самая частая ошибка — перенести
рабочий `when` в `if` и ждать того же; мод скажет об этом сразу, а не промолчит
и не уведёт провайдер в запасные. Неизвестное имя (например, от ещё не
установленного аддона) — наоборот, не ошибка: это просто «условие не
выполнилось».

**Знак перед `{` обязателен,** как и у `when`: `if = { ... }`, а не `if { ... }`.

### Плейсхолдеры

| Плейсхолдер | Значение |
|---|---|
| `{username}` | Имя профиля игрока |
| `{uuid}` | UUID без дефисов (нижний регистр) |
| `{name}` | Имя провайдера |
| `{root}` | Папка игры (для локальных файлов) |

### Лимиты памяти

```
limits {
    maxPixelsPerFrame = 4000000   # Макс. пикселей в кадре (≈2000×2000)
    maxFrames         = 100       # Макс. кадров в анимации
    maxBytesPerCape   = 67108864  # Макс. байт на один плащ (64 МБ)
    maxBytesTotal     = 134217728 # Суммарно на все плащи (128 МБ)
}
```

При превышении лимитов применяется многоступенчатая деградация: сжатие → прореживание кадров → удаление из кэша. FPS не просаживается.

### Синхронизация с сервером

```
serverSync {
    enabled              = true   # объявлять свой набор и брать чужие
    shareLocalProviders  = false  # отдавать другим свои ЛОКАЛЬНЫЕ файлы
    allowForeignUrls     = false  # выполнять чужие объявления с http/json
    backoff              = true   # замедлять докачку при неудачах
}
```

Как это работает: ты объявляешь серверу свой набор функций, сервер рассылает
всем снимок, и каждый считает приоритет **своего** набора и условия **чужого**
плаща против мира того, на кого смотрит. Поэтому джунглевый плащ видно и из
пустыни: важно, где стоит владелец, а не где стоит зритель.

Три настройки, которые стоит понимать до включения:

- **`shareLocalProviders`** по умолчанию выключен намеренно: `true` означает,
  что байты твоего плаща уезжают на сервер и оттуда ко всем остальным. Локальный
  файл — это личное. `http`/`json` и так видны всем, кто откроет ссылку, там
  отдельного согласия не нужно. Путь на провод не уходит никогда — вместо него
  передаётся SHA-256, а байты забираются у владельца через сервер.
- **`allowForeignUrls`** по умолчанию выключен: иначе любой в чате может
  объявить функцию, чей адрес указывает на его хост, и каждый, кто на тебя
  посмотрит, схватит этот адрес — это превращает твой рендер в маячок. Включай
  только если доверяешь всем в лобби.
- **`backoff`** относится к докачке картинок, а не к опросу: опроса в v4 нет
  вообще, сервер сам рассылает снимки при изменениях.

Ключи `intervalTicks`, `timeoutTicks`, `requireServer` и `allowFileProviders`
относятся к протоколу 1.x и **игнорируются**. Если они есть в твоём конфиге —
можно удалять.

**Протокол v4 несовместим с 1.1.x.** Версия проверяется первым байтом пакета, и
несовпавший пакет отбрасывается на разборе. Симптом после частичного обновления
выглядит так, будто плащи просто перестали приходить: внятной ошибки в чате нет,
в обычном логе тоже ничего (на сервере запись есть, но уровнем `debug`). Если
плащи пропали — сначала сверь версии на сервере и на всех клиентах и доведи до
одной.

**Что едет по сети.** В объявление попадают и `when`, и `if` — получатель сам
считает их у себя, по наблюдаемому игроку и по своим переменным. Поэтому
`if = { username: "Eonixx" }` реально ограничивает показ конкретному владельцу
на всех клиентах, а не только локально. Исключение одно: условие `state` не
уезжает никогда, см. выше.

Сервер проверяет форму объявлений и лимиты, но не решает, кто что носит: он не
сверяет картинку с объявлением и не хранит игроков после рестарта. Правду
объявления проверяет каждый клиент сам — отсюда и `allowForeignUrls`.

### Переменные окружения в `.kn`

Любое значение можно взять из переменной окружения. Работает и в кавычках, и
без них:

```
capeCraft {
    providers [
        { name = "cdn", type = "url",
          url = "https://${CAPE_HOST:-cdn.example.com}/capes/{username}.png" },

        { name = "api", type = "json",
          url = "https://${CAPE_HOST}/cape?u={username}", extract = "$.data.url" }
    ]
}
```

| Запись | Поведение |
|---|---|
| `$NAME` | значение `NAME` |
| `${NAME}` | то же самое, границы подстановки видны явно |
| `${NAME:-дефолт}` | значение, а если переменной нет **или она пустая** — дефолт |
| `$$` | буквальный `$` |

**Имя переменной** — буквы, цифры, `_` и `-`, причём начинаться оно должно с
буквы или `_` (`$1BAD` — это текст, а не переменная). Всё остальное имя обрывает:
при `BASE=localhost:8080` запись `url = "$BASE/api/cape.png"` даст
`localhost:8080/api/cape.png`, потому что на слэше имя кончилось, а хвост
дописался как есть. Так же ведут себя точка, запятая, двоеточие и пробел.

Дефолт отделяется только `:-`, как в `sh`. Одиночный `-` разделителем быть не
может — он же часть имени, и `${A-B}` это переменная `A-B`. Если нужен дефолт
для такой переменной, пишите `${A-B:-фолбэк}`.

Без кавычек составное значение тоже работает, пока начинается с `$`:
`url = ${HOST}/capes/${PORT}.png`. Если перед подстановкой есть свой текст —
бери кавычки: `"a${HOST}b"`. Без кавычек такая запись не является значением и
конфиг не загрузится.

**Незаданная переменная — не поломка конфига.** На её место подставляется пустая
строка, конфиг грузится целиком, а в лог один раз на имя уходит предупреждение с
её именем: молча пустой `url` выглядел бы в логе так же, как заданный адрес, и
плащ просто перестал бы грузиться. У незакрытой подстановки и неверного имени
ошибка по-прежнему есть, и называет она место и текст.

**Подстановка всегда даёт строку.** `maxFrames = "${CAPE_FRAMES}"` числом не
станет: мод не сможет прочитать поле и напишет в лог, что ожидал число, что
получил строку, и каким переопределением это правится. Для чисел и флагов
нужны точечные переопределения из следующего раздела — `CAPECRAFT_LIMITS_MAXFRAMES`
или `-DcapeCraft.limits.maxFrames=20`. Подстановка годится для строк: адресов,
путей, имён провайдеров.

### Настройка через окружение и аргументы JVM

Нужно там, где в папку игры положить файл нельзя: выделенный сервер под
systemd или лаунчер. Работает и на клиенте, и на сервере.

В Prism/FreesmLauncher у инстанса есть и переменные окружения, и аргументы
JVM — это поля `Env`/`OverrideEnv` и `OverrideJavaArgs` в `instance.cfg`.
Надёжный путь — аргументы JVM: допиши в поле с ними
`-DcapeCraft.limits.maxFrames=20` и перезапусти инстанс. Переменные
окружения задаются списком Name/Value рядом с галочкой Override Global
Settings; без галочки инстанс наследует только глобальный список.
Что из этого реально подхватилось — видно в `/cp status`.

**Весь конфиг целиком** — один файл вместо `config/capecraft.kn`:

```bash
CAPECRAFT_CONFIG=/etc/capecraft/prod.kn
```

Формат тот же, поддерживает всё, включая провайдеров. Единственный способ
задать провайдеры из окружения.

**Точечные переопределения** — для лимитов и синхронизации. Имя строится
механически: префикс `CAPECRAFT_`, верхний регистр, всё кроме букв и цифр
заменяется на `_`:

| Ключ в `.kn` | Переменная | Аргумент JVM |
|---|---|---|
| `capeCraft.limits.maxFrames` | `CAPECRAFT_LIMITS_MAXFRAMES` | `-DcapeCraft.limits.maxFrames=20` |
| `capeCraft.limits.maxBytesTotal` | `CAPECRAFT_LIMITS_MAXBYTESTOTAL` | `-Dcapecraft.limits.maxBytesTotal=268435456` |
| `capeCraft.serverSync.enabled` | `CAPECRAFT_SERVERSYNC_ENABLED` | `-Dcapecraft.serverSync.enabled=false` |
| `capeCraft.serverSync.shareLocalProviders` | `CAPECRAFT_SERVERSYNC_SHARELOCALPROVIDERS` | `-Dcapecraft.serverSync.shareLocalProviders=true` |
| `capeCraft.serverSync.allowForeignUrls` | `CAPECRAFT_SERVERSYNC_ALLOWFOREIGNURLS` | `-Dcapecraft.serverSync.allowForeignUrls=true` |

Приоритет: переменная окружения → `-D` → файл `capecraft.kn` → дефолт.
Флаговые значения понимаются как `true/yes/on/1` и `false/no/off/0`.
Нечитаемое значение не ломает мод: берётся значение из файла, в лог уходит
предупреждение с именем переменной — опечатку видно сразу, а не через
неделю. Актуальные значения показывает `/cp status`.

## Команды

Все команды клиентские — работают в одиночке и на сервере без прав.

| Команда | Действие |
|---|---|
| `/cp reload` | Полная перезагрузка: конфиг с диска, новый набор провайдеров, кэш и GPU-текстуры в ноль, немедленный запрос синхронизации |
| `/cp clear` | Только кэш: плащи перекачаются при следующем обращении, набор провайдеров и настройки не меняются |
| `/cp list` | Диагностика отбора: цепочка провайдеров, победитель, фактическое и ожидаемое значение каждого `when`/`if`, совпал ли с тем, что реально применено |
| `/cp status` | Версия, число провайдеров/плащей, память, активные переопределения из окружения |
| `/cp sync` | Объявить свой набор заново и показать ревизию роустера — вручную, без перезагрузки конфига |

**`/cp list` — главный инструмент, когда плащ не тот.** Команда не гадает: она
пересчитывает отбор тем же кодом, что и рендер, и печатает каждое условие с
обеих сторон. Так видно, где именно цепочка перестала идти:

```
Провайдеров: 4. Отбор для Eonixx.
Цепочка загрузки: rain → night → storm → default
На экране: storm
× rain — не подходит
      ✗ weather.condition: thunder rain
      ✓ time.period: night night
+ night — условия выполнены
      ✓ weather.condition: thunder thunder
→ storm — условия выполнены
      ✓ time.period: night night
× default — без условий, всегда в цепочке
Плащей в памяти: 2, 786432 байт
```

Условие печатается как `путь: в мире → ожидали`. `✗ weather.condition: thunder
rain` читается как «в мире `thunder`, ждали `rain`» — поэтому `rain` и отсеялся.
`→` — победитель отбора, `+` — прошёл, но проиграл по приоритету, `×` — не
прошёл. Фраза «без условий, всегда в цепочке» у последнего провайдера означает,
что он сработает, только если не подошёл ни один условный, — это нормальное
поведение, а не ошибка.

Отдельно выводится «Плащей в памяти» с суммарным объёмом; если плащей нет, а
ошибки загрузки есть, вместо счётчика печатаются сами ошибки — по ним видно,
почему картинка не приехала.

`/cp reload` сбрасывает и авторитетность сервера — после него действует
локальный конфиг, пока сервер не ответит снова. Плащ на время загрузки
исчезает (рисуется ванильный): сохранить старую текстуру значило бы сохранить
ровно то состояние, которое сбрасывается.

## Форматы

| Формат | Анимация | Прозрачность | Примечание |
|---|---|---|---|
| PNG | — | tRNS | Статичные плащи |
| Stacked PNG | да | да | Кадры друг под другом; размер кадра в служебном чанке `Description` |
| APNG | да | да | Полная композиция кадров |
| GIF | да | да | LZW, интерлейс, NETSCAPE2.0 |
| WebP (lossless) | да | да | VP8L, ANMF-анимация |

Формат определяется автоматически по сигнатуре файла — расширение не важно.

**Stacked PNG** — обычный PNG, в котором кадры анимации сложены вертикально.
Мод узнаёт его по служебному чанку `tEXt` с ключом `Description`:

```
Description  Stacked PNG: 13 frames 256x128, order=down
```

Формат объявляет себя сам, поэтому размер кадра не угадывается по высоте: без
такого описания обычный плащ 256×512 превратился бы в «анимацию» из четырёх
растянутых кусков. Поддерживается только `order=down`. Если описания нет, высота
кадра считается как половина ширины — этого достаточно для файлов, собранных
старыми версиями.

## Производительность

- Фоновая загрузка: декодирование идёт на отдельном потоке, рендер никогда не блокируется
- GPU-текстуры обновляются ~15 раз/сек по игровому времени, а не на каждый кадр рендера
- UMA-память под контролем: LRU-кэш с жёсткими лимитами
- Адаптивная деградация: слишком большие плащи сжимаются, не убивая FPS

## Аддоны

CapeCraft расширяется сторонними модами: свой тип провайдера, свой формат
картинки, свои плейсхолдеры, свой конфиг, свои события и модификаторы рендера.

Аддон — обычный Fabric-мод, который регистрируется через entrypoint
`capecraft:addons` и реализует `CapeAddon`. Версию API аддон проверяет сам при
загрузке, чтобы не разойтись с модом:

```json
{ "entrypoints": { "capecraft:addons": ["com.example.MyAddon"] } }
```

```kotlin
class MyAddon : CapeAddon {
    override fun register(api: CapeApi) {
        api.sourceTypes.register(CapeSourceType("github") { values ->
            CapeSource { fetchCape(values.entries["repo"] as String) }
        })
    }
}
```

Ключи аддонских типов редактор тоже подсказывает: аддон кладёт в корень своего
jar'а файл `capecraft-addon.kn` с перечнем своих типов, ключей и плейсхолдеров —
редактор читает его из папки `mods` рядом с конфигом. На игру файл не влияет,
подробности в [API.md](API.md).

**Документация: [API.md](API.md)** — все реестры, entrypoint, конфиг аддона,
дескриптор для редактора, события, модификаторы рендера и миграция. Готовый
рабочий пример — в
`versions/<mc>/src/test/kotlin/dev/ggtv/capecraft/examples/ExampleCapeAddon.kt`.
